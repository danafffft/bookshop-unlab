# Безкоштовне розгортання: Render Free + Neon Free

Статус: файли підготовлено. Хостинги ще не підключені; опублікованої адреси немає.

Ця конфігурація зберігає потрібний стек: Go + ASP.NET Core + PostgreSQL. Обидва сервери працюють в одному безкоштовному Docker web service на Render, а база — в окремому Neon Free. Реєстрації, замовлення й каталог зберігаються в Neon і не залежать від тимчасових файлів Render.

## Реальні обмеження безкоштовного варіанта

- Постійна HTTPS-адреса, доступна з інтернету, не потребує увімкненого домашнього ПК.
- Render Free засинає після 15 хвилин без вхідних запитів. Наступний запит запускає сервер, що займає приблизно хвилину. Це не гарантія безперервної роботи 24/7 і не рекомендований Render тариф для робочого магазину.
- Render надає 750 безкоштовних instance-hours на workspace за календарний місяць. Також є ліміти трафіку та збірок. Один контейнер із Go та .NET економить спільні години порівняно з двома сервісами.
- Neon Free: $0, без строку пробного періоду; поточні квоти — 1 GB даних та 100 CU-hours на проєкт щомісяця. База також засинає без активності. Квоти й умови можуть змінюватися.
- Для суворої відсутності списань використовуйте тільки Free, не підключайте платні доповнення й не додавайте платіжний метод. При перевищенні безкоштовних квот сервіс може призупинитися.
- Не використовуйте Render Free Postgres для постійних даних: така база має строк 30 днів. Тут вона навмисно замінена Neon.

## Розгортання

1. Підключити акаунти Render і Neon. У Neon створити проєкт на Free, бажано в європейському регіоні.
2. Отримати PostgreSQL connection string із Neon. Зберегти URL лише як секрет DATABASE_URL у Render, зі збереженими SSL-параметрами. Не надсилати пароль у чат і не комітити URL до Git.
3. Завантажити вихідний код у власний GitHub-репозиторій. Корінь має містити render.yaml, api/, gateway/, db/, web/, deploy/.
4. Створити Render Blueprint із render.yaml. У ньому явно встановлено plan: free. Задати DATABASE_URL, ADMIN_EMAIL та унікальний ADMIN_PASSWORD (12+ символів).
5. Після збірки Render видасть HTTPS-адресу. PUBLIC_ORIGIN автоматично береться з RENDER_EXTERNAL_URL. Для власного домену задати точне PUBLIC_ORIGIN вручну без кінцевого слеша.
6. Дочекатися успіху /api/health. Перевірити реєстрацію, замовлення, адмінпанель та збереження даних після перезапуску.

Зовні доступний тільки Go. ASP.NET слухає 127.0.0.1 всередині контейнера; це внутрішній зв’язок між процесами, відвідувачам localhost не потрібен. Cookie позначені Secure/HttpOnly, запити зміни даних перевіряють HTTPS-origin.

При завершенні будь-якого серверного процесу завершується весь контейнер. Перезапуском і холодним стартом керує Render. Спеціальне штучне утримання безкоштовного сервера активним не використовується.

## Стан перевірки

Go-тести та збірка .NET пройшли після додавання підтримки порту хостингу. Docker-образ Render ще не зібраний на хостингу; повний зовнішній сценарій не перевірений без підключених акаунтів.
